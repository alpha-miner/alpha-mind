# Universe Definitions and Composition

Universes are defined in `alphamind.data.engines.universe` and queried through the SQL engine. A universe does not store a security list; it compiles its definition into filter conditions on the Universe table.

## Basic universes

```python
from alphamind.data.engines.universe import Universe

hs300 = Universe("hs300")
zz500 = Universe("zz500")
```

Names are converted to lowercase and mapped to identically named columns in the Universe table; a value of 1 means the security belongs to the universe. Available names depend on the database schema and commonly include `hs300`, `zz500`, `zz800`, `zz1000`, `sh50`, and `zxb`.

## Querying codes and panels

```python
codes = engine.fetch_codes("2026-01-06", hs300)
panel = engine.fetch_codes_range(
    hs300,
    start_date="2026-01-01",
    end_date="2026-03-31",
)
```

- `fetch_codes` returns a sorted code list.
- `fetch_codes_range` returns an Arrow table containing `trade_date` and `code`.
- Range interfaces also accept `dates=[...]` to query only specific dates.

## Set operations

```python
combined = hs300 + zz500
intersection = hs300 & zz500
difference = hs300 - zz500
also_intersection = hs300.isin(zz500)
union = hs300 | zz500
```

The corresponding types are `OrUniverse`, `AndUniverse`, and `XorUniverse`. The current `-` implementation means “in the left universe and not in the right universe,” namely set difference. Both `+` and `|` denote union; both `&` and `isin` denote intersection.

## Serialization

```python
from alphamind.data.engines.universe import load_universe

description = combined.save()
restored = load_universe(description)
assert restored == combined
```

The description contains the node type, name, or left and right child nodes and can be embedded in `DataMeta` and model configurations. Loading an unknown `u_type` raises a key error, so configurations should be generated by a trusted application.

## Combining universe, factor, and return queries

```python
factors = engine.fetch_factor_range(
    hs300,
    {"rank": "EMA5D"},
    dates=["2026-01-05", "2026-01-06"],
)
returns = engine.fetch_dx_return_range(
    hs300,
    dates=["2026-01-05", "2026-01-06"],
    horizon=1,
    offset=1,
)
```

The engine queries the universe first, then restricts market, industry, benchmark, and risk data. When a local Parquet workflow has no SQL Universe table, filter Arrow tables directly; there is no need to emulate a database universe for local research.
